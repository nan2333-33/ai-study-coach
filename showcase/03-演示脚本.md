# 演示脚本

> 这一份是给你自己看的，不是给面试官的。目标是 3 分钟讲完、现场不翻车。

---

## 一、3 分钟口播稿

### 0:00 - 0:30　痛点（说人话，别说功能）

> 「我自己在学大模型课程，最大的问题是**资料看完就忘**。
> 市面上的工具都只解决一半：Gemini Notebook（原 NotebookLM）能对着资料提问、能出题、还能给掌握度看板，
> 但它不告诉我**这一周相对上一周**有什么变化；
> RemNote 能安排复习，但它没法回答我关于自己资料的问题。
> 中间这一段——**学了之后到底记住没有、下周该回头看哪些**——没人管。」

要点：**先说痛点，不要上来就说功能**。这 30 秒决定他要不要继续听。

**这三句千万别说**（2026-10 复核后已失效，说了会被追问打脸）：

- 「竞品不做测评」——Gemini 学习笔记本已有诊断测验 + 随堂练习
- 「竞品没有进度跟踪」——它已有实时掌握度看板（强项 / 待加强 / 未开始）
- 「我管追踪，它不管」——只剩**跨周期**这一段它不管

### 0:30 - 1:30　演示（照下面第二节的路径点）

边点边说，每步一句：

> 「传一份 PDF → 系统自动切块、向量化 → 我现在问它一个问题，注意回答下面会**标出引用来源**，
> 点开能看到原文片段，这是我防幻觉的做法 → 然后基于这份资料自动出题，提交后自动批改 →
> 所有做过的题会按知识点聚合成**掌握度** → 最后每周出一份周报，可以导出 Word / PDF。」

要点：**慢一点，让对方看清界面**。来源引用和掌握度是两个视觉亮点，一定要停留。

### 1:30 - 2:30　讲一个决策（只讲一个，讲透）

推荐讲 **D-03（学习时长 → 答题数）**，这是最能体现判断力的一条：

> 「有个取舍我想专门说一下。最初的 PRD 和竞品分析都把『学习时长』列为 P0，
> 我做到一半把它**整个砍掉了**。
>
> 因为这个数只能靠事件时间戳的间隔推算——系统自己也证明不了它等于用户真实花的时间。
> 如果用户明明学了 20 分钟，我给他写 190 分钟，他一对发现不对，
> 会连带着怀疑正确率、掌握度这些**本来真实**的数据。
>
> 我换成了答题数：答一题落一条数据库记录，用户可以对着题目数核对。
> 代价是少一个看起来很专业的指标，但**投入指标不能当产品价值**，产出指标才行。」

要点：**主动说出"我砍掉了什么"**，比说"我做了什么"更有说服力。
如果时间够，再补一句：「数据也印证了——28 个知识点里 22 个还是薄弱，正确率 30.5%，
说明出题覆盖够了但复习没跟上，下一版就该补间隔重复。」

### 2:30 - 3:00　下一步 + 诚实收尾

> 「下一版我做间隔重复——竞品分析里我判它是 P0，但为了先跑通闭环把它降到了 P1，
> 现在数据证明它最该补。而且复核完竞品之后我更确定：它是**唯一还剩算法壁垒**的空白，
> 周报能被堆功能追上，复习调度不能。」
>
> 坦白说，目前只有我一个用户，缺的是规模验证，不是功能完整性。」

要点：**不要编用户数据，也不要道歉**。说清自己缺什么，反而是加分。

## 二、演示路径（照这个点，别现场找）

```
1. 资料库    → 展示已解析的 2 份资料、23 个知识块
2. 问一问    → 提问 → 等回答 → 展开「引用了 N 处资料」★ 停留
3. 测评      → 选资料生成测验 → 提交 → 看逐题批改
4. 进度      → 雷达图（只画 TOP 8）+ 知识点列表（熟练 4 / 掌握 2 / 薄弱 22）★ 停留
5. 报告      → 生成周报 → 下载 Word / PDF
```

**提前准备**：演示前先跑一次 `test_e2e_live.py` 确认全绿，避免现场翻车。
如果怕网络慢，提前生成好一份周报放着。

## 三、预判提问清单

| 他可能问 | 怎么答 |
|---|---|
| **你怎么衡量这个产品算成功？** | 北极星：周活跃用户每周净增的已掌握知识点数。护栏是正确率须落在 60~85%（防止靠出简单题刷指标）。拆成活跃人数 × 测评覆盖 × 转掌握率。 |
| **和 Gemini Notebook（原 NotebookLM）有什么区别？** | 不比前半段，它「传+聊」本来就更强。也不比实时看板——它 2026 年已经上了。**只比跨周期**：它给的是「此刻我在什么水平」，我给的是「这周比上周进步了多少、下周该干什么」。前者是快照，后者是轨迹。 |
| **它要是也做周报了呢？**（很可能被追问） | 那就只剩间隔重复。所以我下一版第一件事就是它——**它是唯一还剩算法壁垒的一块**：周报能被堆功能追上，SM-2 类复习调度不能。 |
| **你有跟踪竞品吗？** | 有。7 月它改名 Gemini Notebook 并上学习笔记本，我复核后发现原来「竞品无进度跟踪」这条判断失效了，已经改了文档并标了修订日期（D-07）。**主动说这个，比说"我一直判对了"更可信。** |
| **有多少用户？数据呢？** | 目前只有我，我是第一个用户，痛点来自我自己。闭环 9 步实测全绿，缺的是外部验证。**不要编数据。** |
| **为什么不做闪卡 / 间隔重复？** | 主动降级了（D-04）。MVP 先验证链跑不跑得通，间隔重复是让链更有效。现在数据已经证明代价——22 个薄弱 vs 4 个熟练。 |
| **周报有什么用？值得做吗？** | 12 款竞品零覆盖（2026-10 复核仍成立）。它同时是留存抓手、分享触发、数据沉淀。竞品最接近的是实时掌握度看板，但那不回答「这周 vs 上周」。 |
| **技术难点在哪？** | 讲 D-05 或 D-06。推荐 D-06 的 embedding 分批（≤10 条）——这个坑只有真跑过才知道。 |
| **学习时长为什么没有？**（如果他注意到） | 正好，讲 D-03。 |
| **如果继续做，下一版做什么？** | 间隔重复 → 错题本 → 周报主动推送。 |
| **你一个人做的？多久？** | 如实说。重点在决策质量，不在工作量。 |

## 四、三份材料怎么用

| 场景 | 给什么 |
|---|---|
| 投简历附作品集链接 | `05-简历项目描述.md`（直接抄进简历）+ `01-产品一页纸.md` + `02-关键决策记录.md` |
| 简历里那一段的措辞 | `05-简历项目描述.md`——含主推版、技术岗变体、每条的写法意图、四句千万别写 |
| 面试前自己复习 | `03-演示脚本.md`（本文件） |
| 面试官追问细节 | 翻 `02-关键决策记录.md` 对应条目（D-01~D-07） |
| 被问「效果怎么样」 | 本地 `学习效果记录.md`（未公开）——每周一行，记的是净增掌握数。公开场合只能说机制，不能报数字 |

**一条原则**：PRD 用来证明深度，一页纸用来让人愿意看，决策记录用来证明判断力。
不要指望任何人读完 1230 行的 PRD。
