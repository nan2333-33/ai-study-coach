# AI 学习助手 — 一页纸

> 基于自己资料的 AI 学习教练。传资料 → 聊资料 → 做测评 → 看进度 → 出周报。
> 数据截至 2026-10-13。

---

## Problem

学大模型课程，资料看完就忘。

现有工具都只解决一半：**Gemini Notebook（原 NotebookLM）** 能基于资料对话、出题、还能给掌握度看板，但它**不回顾跨周期的学习轨迹**；**RemNote** 有成熟的间隔重复，但不能对自己的资料提问。**没有任何一款**把「这一周到底学会了什么、下周该干什么」周期性地交还给用户。

结果是：资料读了、笔记记了，但没人告诉你「哪些真的记住了、哪些该回头看」。

## Solution

把自己上传的资料变成可对话、可检验、可追踪的学习对象：

| 环节 | 做法 |
|---|---|
| 传资料 | PDF / PPT / Markdown 自动解析、语义切块、向量化 |
| 聊资料 | RAG 对话，**每条回答附来源引用**，可点开看原文片段 |
| 做测评 | 按资料自动生成选择 / 判断 / 简答，客观题自动批改、简答题由模型改卷 |
| 看进度 | 按知识点聚合掌握度，输出雷达图与薄弱点清单 |
| 出周报 | 每周汇总做题量、覆盖率、正确率趋势、薄弱 TOP3、下周计划 |

与竞品的核心差异不在某一步做得更好，而在**最后一公里**：竞品的进度是「此刻的快照」，周报是「跨周期的轨迹」；竞品的复习要用户自己想起来，间隔重复由系统排。

> **复核（2026-10-13）**：Google 于 7 月把 NotebookLM 更名为 Gemini Notebook，并上了「学习笔记本」——诊断测验 + 实时掌握度看板。
> 所以「看进度」**已不是独家**。护城河收窄到两点：**跨周期复盘（已实现）+ 间隔重复调度（下一版）**。
> 我选择如实写在这里，而不是删掉——竞品追上来这件事本身，比一个漂亮的对比图更能说明我做过什么判断。

## Metric

**北极星：周活跃用户每周净增的已掌握知识点数**

| 层 | 内容 |
|---|---|
| 拆解 | 活跃人数（← 周报召回）× 测评覆盖（← 传资料·聊资料）× 转掌握率（← 测评·进度） |
| 护栏 | 平均正确率须落在 **60~85%** —— 只数「掌握」会诱导出简单题，必须同时约束难度 |
| 辅助 | 「答题数 ÷ 掌握数」比值，防止退化为刷题但不进步 |

## Tradeoff

**砍掉了「学习时长」。**

初版 PRD 和竞品分析都把它列为 P0。实现时发现它只能靠事件时间戳的间隔**推算**——系统自己也拿不出证据证明它等于用户真实花的时间。

一个学习产品摆一个自己算不出来的数，用户一旦发现对不上（明明只学了 20 分钟却写 190 分钟），会连带着怀疑正确率、掌握度这些**真实统计**的数据。

改用**答题数**：`quiz_answers` 的行数，答一题落一条，硬计数可核对。代价是少一个「看起来很专业」的指标。

> 取舍原则：**投入指标不能当北极星，产出指标才行。** 时长是投入，掌握度是产出。

## Status

**五功能闭环已跑通**，9 步端到端实测全绿，45 项前后台契约测试通过。

| 当前数据 | 值 |
|---|---|
| 资料 / 知识块 / 知识点 | 2 份 / 23 块 / 45 个 |
| 掌握度分布 | 熟练 4 · 掌握 2 · **薄弱 22** |
| 累计答题 / 测验次数 | 86 题 / 14 次 |
| 平均正确率 | 30.5% |

> 上表是 2026-10-13 的**基线快照**。每周追踪见根目录 `学习效果记录.md`——
> 记的是「每周净增已掌握知识点数」，也就是下面 Metric 里那颗北极星。

**诚实说明**：第一个用户是我自己，暂无外部用户。缺的是规模验证，不是功能完整性。

**数据已经暴露了真问题**：28 个知识点里 22 个薄弱、仅 4 个熟练，平均正确率 30.5%。
出题覆盖面够广，但**答过一次没再回头**——这恰好是「间隔重复暂时缺席」的代价，也正是下一版该做的第一件事。
